- 「就做 / 选 / 拍板 / 生成 … 详细文档与流程图」+ 能对应到候选表或代码里的某一功能
- 用户从上一轮候选列表里点名（序号或短名）

**禁止**：propose 阶段「先做完再问你要不要改」。必须先交名单。

#### 已有候选页（跨 session 复用）

`flows/{domain}.md` 已在磁盘上时，**先读再决定**，不要默认为空仓。

「可用候选页」= 有带 `slug` 列的表，且至少 1 个 slug。只有骨架链、没有 slug 表 → 当不存在，走完整 propose。

「刷新」信号（命中任一）：`重扫` / `刷新候选` / `重新打分` / `重新探测功能`。

| 已有页状态 | 本轮未拍板、也未说刷新 | 做什么 |
|---|---|---|
| 等待选择，表里有 slug | **只复述**未深挖名单（可含已深挖行作对照），请拍板 | 不跑第 6 节聚类打分；不改该文件；不重写 `layers.md` |
| 部分行已深挖，其余等待 | 复述**未深挖**的，请拍板 | 同上 |
| 全部已深挖 | 复述并说明「该域候选都已深挖」；问要刷新还是指定 `feature=` 再深 | 不重扫、不自动 deep |
| 用户说了刷新 | 再跑聚类打分，覆盖候选表 | **已深挖行保留** slug / 链接 / 状态；只重算等待中与新增项 |
| 无文件或不是候选表 | 完整 propose | 与原来相同 |

无 `domain=`：不走两步协议；**不写** `flows/`，对话提示带 `domain=` 再调研。

### 6) 功能探测（仅 `mode=flows` 且带了 `domain=`）

「功能」= 同一业务动作的一组入口，不是一条路由一行。  
禁止用其它系统的业务外号当功能名。

#### 聚类

从该域入口归并（`api-list` / `cli-and-consumers` / 打开的 controller、console、consumer）。

若存在 `docs/agents/03-deep-dives/critical-paths.md`：**先读再聚类**。起点接口所属的功能在同分时优先进入 Top 3～5；禁止把链路表一行直接当成 slug，仍按入口归并。

| 归并信号（命中任一即可合成一个功能） |
|---|
| 同一 Controller 上的一组写操作（如 store / review / import） |
| 同一 Consumer `name` 或同一 `*StrategyProvider` / 同一 chain 类 |
| 写入同一核心 Model（表名相同，取自本轮剖面节的 Model API） |
| HTTP/CLI 投 MQ，由同域 Consumer 接着做 → **算同一功能**，不拆成两个 |

功能短名（`slug`）优先级：路由注释 / action 注释 → Consumer yml `name` → Controller 去 `Controller` 后缀 + action-id。只允许 `[a-z0-9-]`。禁止自创中文产品名当 slug。

#### 重要性（过滤）

| 分 | 信号（须在本仓库代码对得上；核心链路加分须该页存在） |
|---:|---|
| +2 | 能追到 F 编排 |
| +2 | 有 L 或 V |
| +1 | 有 X 或 MQ |
| +1 | 同时有 HTTP 与 CLI/Consumer |
| +1 | 该功能的入口出现在 `critical-paths.md` 的起点列（文件存在才加） |

重要性 = 0：进「未展开」，不进候选榜。  
例外：入口已在 `critical-paths.md` 起点列时，重要性至少记 1，进入打分，不进未展开。

#### 复杂度（排序用）

只对重要性 > 0 的功能打分。数字必须来自本轮打开的代码。

| 分 | 信号 | 怎么数 |
|---:|---|---|
| +4 | V 很宽 | Provider `providers()` ≥ 3，**或** chain `apply()` / 同类列表 ≥ 5 个算子 |
| +4 | 调用深 | 入口到写库中间编排类 ≥ 4 跳（controller 不算） |
| +3 | 分支多 | 主路径上按 status/type/mode/platform 等字段的 `if`/`switch` ≥ 3 |
| +3 | 多表写入 | 不同表名 ≥ 3 |
| +2 | 有状态机 | 带 `getNext*` / 明确禁迁的 Status/State |
| +2 | 批处理 | 列表/文件行/item 循环后落库或投 MQ |
| +2 | 跨入口 | HTTP/CLI 投递，计算在 Consumer/task |
| +1 | 事务/锁/幂等 | 代码里有 `transaction` / lock / 去重键 |
| +1 | 对外 | launcher / internal / OSS 等 |

propose：按复杂度取 **Top 3～5** 进候选榜（不足则有多少列多少）。同分优先更深、V 更宽。

#### propose 产出（只推荐）

1. 更新 `flows/{domain}.md`：候选表（见下）+ 未展开索引；**不要**写各功能长步骤
2. 在对话中用同样表格请用户拍板（序号或 slug）
3. **停止**。禁止创建 `flows/{domain}-{slug}.md`、禁止画 `diagrams/flows/*.svg`、禁止因本轮去扩写 lifecycle/contracts 细节

```markdown
|---|------|--------|---------------------------|-------:|-------:|----------------------|
| 1 | … | … | … | … | … | V=…；跳数=…；… |

```

未展开表 ≤ **10** 行，其余写「其余 N 个入口不展开」。禁止把未展开写成第二份候选榜。

对话收尾必须包含：

```text

使用 codex-map mode=flows domain=<域> feature=<slug|自然语言>
```

`refresh=cited`：不 propose、不 deep、不重画图。按 `quality.md`「行号证据」核对已有深页（有 `domain=` 只核该域），对不上的行标 `已过期`，然后 summary。

#### deep 产出（拍板后才写）

每个拍板功能：点名 `feature=` 只重写这一个功能，不重写清单。已有 `## 人工补充` 整节保留到文末。

1. `flows/{domain}.md`：把该行标为「已深挖」，链到深页和 `flow.html`
2. `flows/{domain}-{slug}.md`：步骤真源（`S1`… 编号，每步有 `路径:行号`）+ 实现细节
3. 只出一份 `diagrams/flows/{domain}/{slug}/flow.html`（见下节）。禁止再拆多张 SVG

用户自然语言对不上唯一候选：列出最接近的 2～3 个再问一次，**仍不深写**。

同功能 HTTP 投 MQ、Consumer 落库：一条时间线、同一套 `S*` 编号、一份细节。

##### 步骤编号（图与代码的接头）

- 主步骤：`S1` `S2` `S3`… 按**业务时间顺序**，不按类名
- 阶段内展开：`S3.1` `S3.2`（只出现在对应 L2 / 调用栈，不塞进 L1）
- **L1 节点 ID = 步骤表 ID = 调用栈表 ID**，三者必须同一套
- 禁止再用「1. 2. 3.」当主编号（可在句子里叙述，表和节点只用 `S*`）

阶段按业务切，不要按目录切。空阶段合并。常见五段（有则用，无则跳过）：

| 阶段 slug | 覆盖 |
|---|---|
| `entry` | 入口、空包、锁、能否跑 |
| `branch` | 按平台 / 策略 / 类型选实现 |
| `compute` | chain / pipeline / 主计算 |
| `persist` | 写库、回写、发出 MQ/HTTP |
| `fail` | catch、补偿、禁迁、ACK |

##### 出哪一张图

判断完整优先于少画。一张页面装下整条流程，子流程默认折叠，不靠拆文件。

| 条件 | 出图 |
|---|---|
| 有深挖 | 只出 `diagrams/flows/{domain}/{slug}/flow.html` |
| 主步骤 | 默认可见，5～9 个 |
| 子流程 | 挂在对应主步骤上，默认折叠。里面还有一段完整故事就再嵌套一层 |
| 分支表里会改下一步的条件 | 展开后能看到菱形。同出口合并。只改数值的不进图 |

```text
docs/agents/diagrams/flows/{domain}/{slug}/flow.html
```

- 目录：`diagrams/flows/{domain}/{slug}/`。**禁止**把图直接铺在 `diagrams/flows/` 根下
- 一个功能一份 `flow.html`。禁止再写 `01-overview.svg` 和 `{nn}-{phase}.svg`
- 深页不要用 mermaid 围栏代替这页
- 旧的流程图 SVG 不再链。本轮重做时删掉该功能目录里被这页替代的 svg

##### 分层流程图（仅 deep）

版式与出图方式以 `references/diagrams.md` 为准。

**优先级（高于节点上限和留白）**

1. 会改变下一步的条件必须是**橙边菱形**，两个出口都接到真实下一步。走向相同的多条收成一个菱形。只改中间数值、不改下一步的行留在分支表，图上用一个步骤带过。
2. 禁止把这种条件写成矩形副行。不合格：「不验库存则跳过」写在「查库存」下面，主链仍然进入查库存。合格：菱形「验库存?」，否进 TMS，是进查库存。
3. 子流程挂在对应主步骤上，默认折叠。一段故事里还有另一段故事，就再嵌套一层，不要拆文件。
4. 多个条件走向同一步时收成 1 个菱形。只改中间数值、不改下一步的判断不进图，留在分支表。禁止为了少画删掉会改下一步的菱形。
5. 纯转发（取字段后立刻交给下一个函数、没有 if）才可以并进相邻节点。

**默认可见的主流程**

- 只放主步骤 `S1`…，**5～9** 个节点
- 每个节点：`S{n}` + 短类名或阶段名。不画算子清单、不画每张表
- 有子流程的节点带 `+`，`id` 用小写步骤号（`s3`）

**展开后的子流程**

- 会改下一步的判断是橙边菱形，两个出口都在
- 判断和写库不合并。每张被写入的表一个节点；字段只写在 md
- 异常出口放在判断旁边
- 失败如果互不衔接，做成同一主步骤下的两个折叠块

节点正文：`S*` + `短类名::方法` / 判断短句 / `写 {table}`。每节点 ≤ 2 行。字段、`$var`、catch 只在 md。  
边标签 ≤ 6 字。  
自检：会改下一步的判断在对应步骤展开后能找到菱形（同出口可共用）。只改数值的行留在分支表。主步骤的每个 `S*` 能在步骤表找到。对不上就重画。

### mode=flows

0. `refresh=cited`：停在本节。不探测功能、不 propose、不 deep。按 `quality.md`「行号证据」核对已有深页（有 `domain=` 只核该域），对不上标 `已过期`，summary 后结束
1. 完成开跑前探测（含第 5 节四层）
2. 若 `docs/agents/01-domains/INDEX.md` **不存在**：按共用节补写；已存在则只给本轮域补「深潜」链接
3. 写 `docs/agents/03-deep-dives/layers.md`
4. **F 本仓库无**：不写 `flows/`、不画图；summary 后结束
5. **无 `domain=`**：**不写** `flows/`、不画功能图；对话说明下一步 `mode=flows domain=<域>`；Summary `phase=n/a`；然后跳到更新 INDEX → Summary
6. **有 `domain=`，未拍板（propose）**：
   - 先读 `critical-paths.md`（若存在），再读 `flows/{domain}.md`，按「已有候选页」表决定复用或重扫
   - **复用**：对话复述名单 → **停止** → Summary 标明 `phase=propose-reuse`、来源文件、候选 slug
   - **重扫 / 首次**：只该域，执行第 6 节聚类 + 打分；写 `flows/{domain}.md`（刷新时保留已深挖行）；对话给出候选并请拍板；**停止**；Summary 标明 `phase=propose`
   - 两种都禁止写细节页、画细图、深写 L/V/X
7. **有 `domain=`，已拍板（deep）**：
   - 解析 `feature` / 自然语言到唯一 slug；对不上则再问，不深写
   - 写 `flows/{domain}-{slug}.md` + `diagrams/flows/{domain}/{slug}/flow.html`（主步骤默认可见，子流程折叠）
   - 更新 `flows/{domain}.md` 该行状态为已深挖，链到深页与 `flow.html`
   - **L 命中**：按本功能回写 `lifecycle.md`（其它 Status 只索引）
   - **V 命中**：更新 `variants/INDEX.md`（名 + 一句话 + 命中功能）
   - **X 命中**：按本功能回写 `contracts.md`
   - 更新 `INDEX.md` 覆盖率
   - 自检：`flow.html` 能打开；默认只见主步骤；`S*` 与步骤表、调用栈对齐
   - Summary 标明 `phase=deep`、slug、`flow.html` 路径
